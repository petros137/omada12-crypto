# 1.3 Καταγραφή απαιτήσεων και περιπτώσεων χρήσης

Ομάδα 12 · Μηχανική Λογισμικού 2026-27 · Υπεύθυνος: Απόστολος Δαγκλής (Αναλυτής & Ελεγκτής)

Πηγή: «Λειτουργίες Εφαρμογής – Ομάδα 12» (κατάλογος λειτουργιών της ομάδας, 22/10/2026).

## Σύνοψη

Η εφαρμογή είναι desktop εργαλείο ασφάλειας προσωπικών δεδομένων σε Java (JavaFX). Έχει **6 ενότητες και
58 λειτουργικές απαιτήσεις**: 24 βασικές (M), 25 σημαντικές (S) και 9 επεκτάσεις (C), οργανωμένες σε
**27 περιπτώσεις χρήσης**, και **12 μη λειτουργικές απαιτήσεις**. Όλη η επεξεργασία γίνεται τοπικά, χωρίς
διαδίκτυο και χωρίς βάση δεδομένων.

**Προτεραιότητα (MoSCoW):** **M** (Must) = απαραίτητη για την πρώτη έκδοση · **S** (Should) = σημαντική,
υλοποιείται αν δεν απειλείται το χρονοδιάγραμμα · **C** (Could) = επέκταση, αν μείνει χρόνος.
Καμία λειτουργία δεν είναι W (Won't) σε αυτή την έκδοση.

**Μορφή ID.** Κρατάμε τα ID ανά ενότητα (ENC, VLT, SIG, STG, LAB, APP) με στήλη «UC». Έτσι από το ID φαίνεται
αμέσως σε ποια ενότητα ανήκει η απαίτηση. Τα ίδια ID χρησιμοποιούν η εφαρμογή αναφοράς, τα σχόλια
`// Υλοποιεί:` του κώδικα και τα tests. _(Πρόταση για την απόφαση #2 του docs/decisions.md.)_

## Μη λειτουργικές απαιτήσεις

Κάθε μη λειτουργική απαίτηση έχει συγκεκριμένο κριτήριο, ώστε να μπορεί να ελεγχθεί (στήλη «Πώς ελέγχεται»).

| ID | Κατηγορία | Απαίτηση | Πώς ελέγχεται |
|---|---|---|---|
| NFR-01 | Ασφάλεια | Κρυπτογράφηση με AES-256 σε λειτουργία GCM, με νέο τυχαίο IV σε κάθε κρυπτογράφηση | Κλειδί 32 bytes, IV 12 bytes· το ίδιο κείμενο με τον ίδιο κωδικό δίνει διαφορετικό κρυπτοκείμενο σε 2 εκτελέσεις |
| NFR-02 | Ασφάλεια | Κλειδιά από κωδικούς με PBKDF2-HMAC-SHA256, τυχαίο salt και 600.000 επαναλήψεις, όπως συνιστά το [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) | Επαναλήψεις = 600.000, salt = 16 bytes, νέο salt σε κάθε κρυπτογράφηση |
| NFR-03 | Ασφάλεια | Κωδικοί και κλειδιά δεν γράφονται ποτέ σε ιστορικό, logs ή δίσκο σε απλό κείμενο | Το αρχείο ιστορικού έχει μόνο 5 πεδία (ημερομηνία, ενότητα, ενέργεια, όνομα αρχείου, αποτέλεσμα)· 0 εμφανίσεις του κωδικού στα αρχεία της εφαρμογής |
| NFR-04 | Ασφάλεια | Ο κύριος κωδικός θησαυροφυλακίου δεν ανακτάται. Ο χρήστης ενημερώνεται κατά τη δημιουργία | Δεν υπάρχει λειτουργία ανάκτησης· η προειδοποίηση εμφανίζεται 1 φορά σε κάθε δημιουργία |
| NFR-05 | Αξιοπιστία | Διακοπή κατά την κρυπτογράφηση δεν αλλοιώνει το αρχικό αρχείο: η έξοδος γράφεται σε προσωρινό αρχείο και μετονομάζεται στο τέλος | Μετά από αποτυχία ή ακύρωση: αρχικό αρχείο ίδιο byte-προς-byte, 0 αρχεία εξόδου |
| NFR-06 | Απόδοση | Κείμενο έως 10.000 χαρακτήρων σε λιγότερο από 1 s. Αρχείο 50 MB με AES σε λιγότερο από 5 s σε τυπικό laptop | Χρονομέτρηση: < 1 s για 10.000 χαρακτήρες, < 5 s για 50 MB |
| NFR-07 | Ευχρηστία | Κάθε βασική ενέργεια ολοκληρώνεται σε έως 3 κλικ από την αρχική οθόνη | Μέτρηση κλικ για κάθε UC με λειτουργίες M: ≤ 3 |
| NFR-08 | Ευχρηστία | Η στεγανογραφία δέχεται PNG ή BMP και αποθηκεύει πάντα σε PNG. Για JPEG εμφανίζεται προειδοποίηση | Αποθήκευση ως «.jpg» δίνει αρχείο .png· είσοδος JPEG δείχνει προειδοποίηση |
| NFR-09 | Διεθνοποίηση | Όλα τα κείμενα της διεπαφής βρίσκονται σε αρχεία πόρων (ΕΛ / EN), όχι μέσα στον κώδικα | Τα δύο αρχεία πόρων έχουν ακριβώς τα ίδια κλειδιά· 0 κλειδιά που λείπουν |
| NFR-10 | Φορητότητα | Τρέχει σε Windows, Linux και macOS με Java 17 ή νεότερη | Εκκίνηση και `mvn test` επιτυχή με Java 17 (σε τουλάχιστον Windows και Linux) |
| NFR-11 | Συντηρησιμότητα | Νέος αλγόριθμος προστίθεται με μία νέα κλάση, χωρίς αλλαγές στη διεπαφή | Προσθήκη αλγορίθμου = 1 νέα κλάση + 1 γραμμή στη Factory, 0 αλλαγές σε controllers/FXML |
| NFR-12 | Ιδιωτικότητα | Λειτουργία χωρίς διαδίκτυο και χωρίς βάση δεδομένων. Κανένα δεδομένο δεν στέλνεται έξω από τον υπολογιστή | Όλες οι λειτουργίες δουλεύουν χωρίς σύνδεση· 0 εξαρτήσεις δικτύου ή βάσης δεδομένων |

αρχεία στις UC-03…06, 09, 11, 16, 17, 20, 22) · **Παραλήπτης** (δευτερεύον: όποιος επαληθεύει μια υπογραφή με
το δημόσιο κλειδί, UC-18).
